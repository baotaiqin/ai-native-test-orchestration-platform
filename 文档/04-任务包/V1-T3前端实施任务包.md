# V1-T3 前端步骤重试实施任务包

主控于 P6-U1/r3 completed/idle 且30项浏览器与主控5项独立复验通过后派发 V1-T3/r1。具体轮次以主控任务台账及主控消息为准；执行任务不自行派发或扩展。

## 前提与目标

Runner V1-T1/r1、Backend V1-T2/r1 均已通过磁盘验收；读取《V1步骤重试上限实施契约》和《V1-T2步骤重试后端交付》。本包统一前端新建、版本编辑、AI 建议接受和执行入口的 0/1 限制，保留旧 2/3 版本及历史结果原值。

## 允许范围

- `frontend/src/views/test-cases/TestCaseView.vue`；
- `frontend/src/views/requirements/components/CaseSuggestionPanel.vue`；
- `frontend/src/views/runs/RunCenterView.vue` 中 API Case 新执行校验和错误引导的必要局部调整；
- 必要独立重试校验 helper、对应类型/API 的兼容调整、Frontend 专项测试；
- `.codex-validation/v1-t3/` 及《V1-T3步骤重试前端交付.md》。

不改 Backend/Runner、P6 报告/证据/Dashboard、认证、正式服务、全局文档或历史验收文件。不重启服务、不运行 AI、不创建正式资产。沿用主控独占调度，禁止跨任务工具、Git 或转交其他执行任务。

## 实现要求

1. 新建 API Case 及新版本只允许数值 0 或 1，说明最多额外重试一次、总尝试最多两次。布尔值、字符串、负数、大于 1 不得在保存前通过 Number/截断/clamp 静默变成合法值。缺省策略保持既有默认 0。
2. 打开历史 2/3 版本、从历史创建新版本时，原数值仍可见；不把组件 max=1 导致的自动修正当作用户选择。可用 0/1 选择器和禁用的旧值选项，要求用户显式选择合法值后才保存新版本。历史详情不改写，打开后取消不得触发写入。
3. AI 建议可以保留旧策略作为草稿，但接受为正式用例前必须符合 0/1。单条和批量接受都给出明确原因；批量任一旧策略不通过时不得局部接受。后端 409 的 `API_STEP_RETRY_LIMIT_EXCEEDED` 和 Run Create 外层 `RUN_VALIDATION_FAILED` 的嵌套 issue 正确显示，不用“可能已经决策”掩盖原因。
4. 主控确认现有 `CaseSuggestionPanel.formResult()` 仅重建标题/步骤等少数属性，会丢失原建议的 request、pre_actions、post_actions、extractors、data_source、assertions、cleanup。修复为从当前建议有效内容的独立副本保留全部未编辑属性，再应用用户明确编辑字段；仅修改重试策略也必须保留其余请求、运行配置和扩展字段。不直接修改原 structured_result；不扩大为完整新请求编辑器。建议保存→接受链路必须锁定点击时的建议ID、需求/项目和编辑内容；await期间切换选择不能把后续接受发给另一条建议。忙碌态、防重复提交与上下文校验须与原修改意图一致。
5. RunCenter 针对选中的 API Case 旧 2/3 版本显示不能发起新执行及新版本修正引导，保留后端 Validate 作为权威门禁。旧 Run 的读取、取消和原完成结果不受影响。不要改 Healing/FailureAnalysis/SSE/Scenario 的状态机；未知或变化后的服务端错误仍清楚展示，不自动修改策略后重试请求。
6. 手工 Case 保存错误使用后端实际错误信息。现有 retry_on、backoff、取消和预算语义保留，Scenario RETRY_ONCE 不改。类型层不把历史读取字段错误缩窄为只有 0/1。

## 验收

类型检查、独立目录 production build，通过真实 Chrome 与明确受控 API 响应验证：新建 0/1、旧 2/3 可读且打开取消零写入、未显式修正不能保存、显式改为 1 创建新版本而旧版本不变、单条/批量建议接受拒绝及错误信息、新 Run 旧策略阻断。捕获请求断言 UI 编辑前后全部非编辑配置保持一致，不能仅验证标题和重试字段；延迟保存时切换建议或需求不得接受其他记录，重复点击不产生重复正式接受。

测试资源使用独立随机回环服务并在 finally 清理；不得访问正式 AI/数据库/中间件。交付脚本、实际命令/结果、截图、SHA256 和遗留项。完成本包后结束，由主控拉取、审查，再单独安排 Backend/Runner 正式加载及只读复验。
