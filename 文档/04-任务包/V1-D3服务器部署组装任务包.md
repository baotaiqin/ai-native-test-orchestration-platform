# V1-D3/r1 服务器部署组装

状态：已由单窗口主控直接实施并通过静态/合成配置基本检查（2026-09-11）。原执行任务授权文字保留为历史，未派发长期任务。

## 目标

在已交付 D1 前端 nginx 和 D2 跨平台 Secret Provider 上，补齐 Backend 镜像、独立服务器 Compose 与运维说明。属于开发交付，真实镜像构建和全栈启动统一后置，不能标记服务器部署已验收。

## 范围

允许 deploy/server/ 内新增 Backend Dockerfile、专用 dockerignore、服务器 compose、必要启动/检查脚本、无真实值的配置模板，以及 文档/01-使用指南/服务器部署运行说明.md、.codex-validation/v1-d3/、文档/05-交付记录/V1-D3服务器部署组装交付.md。D1文件仅做实际组装所需的最小兼容修改并说明理由。禁止修改 backend/runner/frontend 业务源码、现有开发Compose、.env、正式数据库和全局台账。

1. Backend 用项目声明的 Python 3.12 与 pyproject 安装依赖，非root运行，明确复制应用和迁移文件，构建上下文默认排除工作区秘密及个人状态。必要可写目录单独提供，镜像不含Fernet密钥或运行身份。
2. Compose 使用独立项目命名，组装 frontend/backend/MySQL/Redis/RabbitMQ/MinIO 和明确持久卷；不使用固定 container_name 抢占现有开发服务。只暴露入口，供 Windows Runner 使用的队列/后端访问另有显式配置与受限绑定说明，不默认把所有中间件公开全部网卡。
3. 生产配置拒绝空值及已有开发默认凭据，APP_ENV=production、APP_DEBUG=false，明确数据库、队列、Redis、MinIO、JWT密钥、CORS。APP_SECRET_PROVIDER=fernet，APP_SECRET_FERNET_KEY_FILE 指向独立只读文件；不得拿JWT字符串充当Fernet密钥。配置模板用缺省即失败的占位约束，不能提供通用密码。
4. 迁移、显式管理员初始化和应用启动分开。当前命令 python -m app.modules.auth.bootstrap --confirm-bootstrap 保留历史 dev-admin ID，不自动执行、不每次启动重设密码。说明升级备份和回退边界；正式库0038与代码0041的差异只记录，不实际迁移。
5. 明确 /health 是进程健康，不伪称所有依赖可用。沿用D1的SPA/API/SSE规则；如提供就绪检查则不得打印连接URL、令牌或配置全量。无需运行真实业务或AI。
6. 镜像版本/可用性无法查实时，标记待真实构建确认，不用latest掩盖不确定性。镜像拉取、Docker启动和Linux现场验证留待集中验收。

只做 YAML/JSON/脚本语法和有限静态配置契约检查，覆盖必填变量、无默认秘密、只读密钥挂载、隔离命名/端口、非root与构建排除、迁移/初始化不自动触发。使用合成占位值解析时不得输出完整配置。不做Docker构建/启动、真实Linux、全套回归或正式操作。
