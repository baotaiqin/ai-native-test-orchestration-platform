## 目标与事务边界

在创建 Run/CaseRun 的同一数据库事务中持久保存需求来源；提交失败时 Run、CaseRun、StepRun 与来源全部回滚，不能提前发出事件或消息。当前 create_run 只有一个 CaseRun，设计按 CaseRun 关联其真实锁定目标，便于未来多 CaseRun；本包不实现数据驱动或增加迭代。

只捕获 I1 中 ACTIVE 的类型正确关联：API_CASE 对应 TEST_CASE 的实际锁定 TestCaseVersion，WEB_CASE 对应独立 WEB_CASE 的实际锁定 WebCaseVersion。精确关联必须匹配执行版本；旧资产级关联可以记录但明确资产版本未知，不能宣称覆盖实际执行版本。其他精确资产版本不属于本次来源。

现有 Scenario 是独立 DSL，不从 URL/名称/相同数字 ID 猜 TestCase 来源；使用明确不适用语义（例如 UNSUPPORTED_TARGET），不把它描述为已证明没有需求。旧 Run 没有捕获标记时保持 NOT_RECORDED；新受支持目标无来源为 CAPTURED_EMPTY，有来源为 CAPTURED。不得回填任何旧 Run。

捕获读取必须来自一个明确的一致数据库视图，不能先枚举链接再逐条读会变化的 current，拼出不曾存在的状态。锁定资产/需求版本引用与展示字段一起取得；后续移除、重关联、改变 current、归档或改名称均不得改变已捕获来源。说明默认 RR 与 RC 下采用的事务/语句边界，真实并发由后续 MySQL 包验证。

## 持久模型与范围

优先独立来源捕获模块和表，CaseRun 关联捕获头与有界条目；允许选择清楚的局部字段命名，不要求大改现有 Run 模型。至少保存捕获状态、可靠 UTC 捕获时间、目标类型与执行版本、原 Link/修订 ID、需求/版本（可未知）、来源/关系/置信度与未知绑定语义。若保存名称/版本号/hash，明确它们是捕获值；不保存 Markdown 正文、请求体、Secret、AI 正文或浏览器会话。

捕获上限暂定每个 CaseRun 1000 条，用 limit+1 检测超限并原子拒绝本次创建；不能静默截断后标 CAPTURED。未知/跨项目/归属不一致的引用必须安全处理，不能把其他项目来源写入可见快照。采用可靠外键/约束，避免来源随物理级联删除而消失；已有归档语义保留。

## 读取与导出

按报告的项目权限返回 CaseRun 捕获状态和分页来源；对同一个 Run/CaseRun 使用持久事实，不在查询或 Dispatch/Claim 时重算。Report 详情、分页与 Markdown/HTML 导出取同一来源，并沿现有只读一致快照和 16MiB 导出边界；嵌入新增来源须计入总大小限制，不能以未展示完的分页冒充完整导出。

旧报告明确未记录，不填空捕获时间或猜 UTC。新的可靠时间使用显式 UTC offset。前端暂可忽略新增字段，后续另包展示；不能为前端暂未支持而改变旧响应字段含义。
