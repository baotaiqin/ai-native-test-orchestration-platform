## 产品行为

在需求工作台接入关联管理及确定性影响分析，TestCase 与独立 WebCase 页面提供反向需求入口。保留已有需求树、版本切换、Diff、AI评审/用例建议和用例编辑行为，沿用现有组件风格。

1. 需求侧明确显示资产种类、名称、记录的需求/用例版本、关联状态及来源。原 TestCase 的 WEB 类型与独立 WebCase 必须可区分，跳转不能只凭整数 ID；目标项目、资产、版本参数由实际路由读取，深链刷新后仍正确定位。
2. 人工新增关联显式选择资产种类、资产、需求版本和用例版本；提交前提供可复核的选择摘要，不以 current 漂移替换用户已选版本。移除保留历史；再次关联显示新修订及前驱，不伪装恢复或覆盖旧版本。归档和只读角色禁止写入，授权历史仍可读。
3. 影响面板提供 from/to 版本选择、内容变化事实、Diff 和稳定分页列表；清楚区分“选定范围变化”与“记录基线到目标变化”。只展示确定性潜在关联范围及人工确认提示，不自动改用例状态、创建版本、调用 AI 或发起 Run。无变化、无关联、基线未知、已移除、请求失败分别展示，不把失败清空后显示无影响。
4. 缺失历史用例版本标明“历史版本未记录”，缺需求来源版本标明未知；当前关联不能显示成旧 Run 快照。时间按最终后端新 UTC/旧未知语义展示，不给无时区旧数据默认套用浏览器当地时区。
5. 反向入口能回到所属需求及适当的版本上下文；前后端资产 ID 同号不能串种类。尚未获取或无权限的详情不显示上一资产的关联。

## 并发响应与写入边界

以项目、需求/资产、所选版本、查询参数和当前身份构成请求上下文。切换、卸载、退出、跨标签页换身份、A→B→A时旧响应不得覆盖新上下文或触发后续写入。尤其需求工作台现有父层 loadTree/selectRequirement/版本列表也是新面板的输入，须一并确保不会把迟到的旧需求重新挂到页面。

显式提交的单次写入如已到达服务器，不冒充取消成功；迟到结果不能继续刷新错误上下文、清空新的编辑内容或显示另一身份的数据。请求失败保留可恢复表单，禁止自动重复提交。用例现有 V1-T3/r2 的 API 重试限制、AI Edit/Accept/Reject 与卸载保护必须回归；P6-X2 的共享 http.ts 身份代际行为保持有效。
