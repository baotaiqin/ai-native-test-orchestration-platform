## 加载顺序

1. 先复核前置报告、主控验收文件和冻结哈希；只读确认没有在途 Run/录制，唯一 Runner 身份及服务现状，保护历史摘要与文件哈希。不要直接沿用旧 PID 当作当前进程。
2. 核对准备停止的 Backend、Worker 精确 PID、启动时间、父子关系、命令身份与所有权，任何不确定均停止并交付检查点。不按名称批量终止、不停止别的测试进程，不输出带凭据的完整命令行。
3. 在无在途业务条件下先停止自己拥有的 Worker，再重载自己拥有的 Backend，健康及新接口就绪后恢复同一已注册 Worker。隐藏启动窗口，沿用原环境、注册身份与安全凭据；不调用注册接口，不重新创建逻辑 Runner。
4. 记录新进程身份、实际加载时间晚于指纹确认、启动前后哈希一致；正式 API OpenAPI 与健康验证，唯一 Runner ACTIVE/ONLINE、WEB READY 和 1/1 容量，无在途 Run/录制，Demo `changed_locator=true`。如果旧服务已停止，只恢复明确属于本项目的服务，不伪造进程连续性。
5. 再次核对保护数据、资产状态和历史文件；完成报告后结束，由主控拉取并单独执行真实 API/Chrome 只读联调。

不能重启 MySQL、Redis、RabbitMQ、MinIO、Frontend、Demo；不重投消息、清理共享队列、执行旧 P5-E 恢复/归档脚本、创建/批准/运行测试资产或调用 AI。本包不修改业务历史。正常登录及只读业务查询允许。
