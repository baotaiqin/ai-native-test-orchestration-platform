### 2026-09-13 AI 测试设计的检查点—API 覆盖编译

1. 定位到 Demo 根需求最新一轮虽生成 30 个检查点，但模型只推荐下载接口且没有填写任何 `check_point_keys`；平台旧校验只验证接口编号存在，因而误把低覆盖结果标记为 AI 成功，并仅额外补出登录依赖，最终界面只显示 2 个 API。

4. 原子检查点、分支拆分、非空关联和真实 API 等硬规则改为平台可信系统指令，独立于可编辑的公共/项目提示词；输入模板使用需求、候选 API、指定 API 三段明确边界，不再把规则混入“指定 API”变量。
5. 领域校验改为返回精确 JSON 路径和中文原因，Repair 可直接知道缺失关联、重复编号、越界 API、不存在检查点、多个分支合并，以及哪些叶子需求既没有生成检查点也没有写入缺口；平台内部补充的登录/清理依赖使用独立决策对象，不受 AI 业务接口非空关联约束。

## 3. 当前关键架构决策

- V1 继续使用 Vue 3 + FastAPI 模块化单体 + MySQL；Redis、RabbitMQ、MinIO 使用本机 Docker Compose；Windows Runner 在本机运行；
- Run 创建前必须按当前 Executor 的真实能力进行 preflight，不能创建注定无法执行的任务；
- Retry 只在 Step 级显式开启，默认最多一次；
- Cancel 使用安全检查点协作取消；Force Stop 通过 terminate 执行隔离子进程实现立即终止，Cleanup 不保证完成并明确记录风险；
- Runner 总超时三层取值（Run 覆盖 → 系统默认），经 execution-plan 下发，与 Step timeout 完全分离；
- API_CASE RabbitMQ V1 信封及既有 execution-plan/start/complete 保持向后兼容；Scenario 采用独立受保护执行计划/完成契约，Runner 只执行锁定的 `scenario_version_id` 快照，Secret/数据库密码不得进入 RabbitMQ/Outbox；
- Runner 断线收口：Redis 只是观察边界，MySQL `last_heartbeat_at` + TTL 是自动收口的双重过期依据；终态 Run 不得被覆盖；不自动 Rerun、不迁移 Runner；
- Runner Slot 是运行时容量信号，当前先实现单 Runner API Slot 动态占用与释放；
- RabbitMQ 运行期断连按明确瞬时故障分类并进行可停止的有界指数退避；恢复时重建连接、Consumer 和 durable topology，认证、权限和 topology 配置错误继续 fail closed；
- Phase 5 新增 `WEB_CASE`，但复用既有 Run/Outbox/claim/隔离/Cancel/Force Stop/总超时主干；RabbitMQ 信封只传稳定标识，Web 版本快照、Session 和 Secret 仅通过 Runner credential 保护的 execution-plan 获取；
- Web V1 只支持 Chrome，先完成确定性结构化 Action 与多 Locator 执行，再开发录制和 AI 整理，最后开发只生成建议、必须人工 Accept/Reject 的 DOM/LLM/Vision 自愈；
- Session Profile、Cookie 和 Storage State 作为敏感资产加密保存、最小下发、禁止进入日志、RabbitMQ、普通 trace 和前端列表响应；
- 模型中心采用“接入渠道 → 模型配置 → 项目任务绑定”三层关系：API Key/Base URL 属于平台级渠道，模型配置只引用渠道并描述模型归属与能力，项目设置只选择主模型/fallback；项目 Secret 只保存测试业务使用的账号、Token 等环境凭据；
- Web Recording 使用独立状态机和持久化模型，但复用既有 WEB routing key、Consumer、WEB Slot 与 spawn 隔离；`WEB_RECORDING` 是显式信封联合分支，不能放宽旧 Run 信封；
- 录制原始事件、AI 整理结果和自愈建议始终是候选内容；只有人工 confirm/accept 才能创建 DRAFT 不可变版本，任何路径都不得自动批准或覆盖正式资产；
- 项目暂不使用 Git 上传、branch、worktree 或 commit 协作；
- Claude 只能由用户明确触发，且与 Codex/Luna 串行写入。
- VSCode 只是 Claude 的本地协作入口；PyCharm 的 `.run` 一键启动配置继续保留，不因本次交接改变运行架构。
