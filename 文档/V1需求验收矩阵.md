## 1. 判定规则

- **待复验**：已有实现或历史证据，仍需与最终版本关联的演示/回归证明。
- **缺口已确认**：源码明确拒绝要求能力、实现仅预览或未发现实际功能入口；必须实现后验收。
- **待核查**：当前证据不足，不能判断完成。
- **通过**：记录对应真实版本、命令/场景、输出和清理结果后才能标记。

### API、AI、报告与部署

- API Request 的 JSON/Form/Multipart/Raw、Auth NONE/BEARER/BASIC/API_KEY、动态登录与401最多刷新一次、Cookie、Header/Query、Runtime/Secret Resolver 必须落在正式执行中。
- 数据驱动必须逐行保留 dataset/version/row_index、脱敏参数快照、iteration结果；数据源包括CSV/Excel/Faker/MySQL/Runtime等规格要求，不能只展示预览。
- AI建议必须经过预览、Accept/Reject/Edit、DRAFT、人工批准；批量审核支持通过、拒绝、删除、Priority、Tag、Requirement关联。
- AI断言保持确定性失败优先FAIL，低置信或冲突REVIEW，不允许模型覆盖确定性失败。
- 报告必须包含 Run/Case/Step/Evidence、摘要统计、API请求响应/提取/断言与Web操作/定位/Evidence/Healing，按权限脱敏；支持规划的Markdown/HTML导出。
- 缺陷草稿应可编辑、复制、Markdown导出；只能生成草稿，不向外部缺陷系统自动提交。
- Dashboard需真实项目数、Case数、今日Run、通过率、Fail、待审核、Runner Online、最近Run，遵守项目权限。
- 服务器部署应提供frontend/nginx、backend、MySQL/Redis/RabbitMQ/MinIO；Windows Runner独立。容器后端不能使用Windows DPAPI，需要经过审计的跨平台加密Provider与密钥配置，不降级加密。
- 所有安全、上传限制、角色与项目隔离、UTC时间、不可变版本、Cancel/Timeout/Cleanup语义和迁移兼容性属于验收前提。
