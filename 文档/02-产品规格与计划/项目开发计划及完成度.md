## 1. 项目目标

本项目面向测试开发岗位的求职展示，目标是实现一套从需求或 Swagger 输入，到 AI 评审与用例生成、人工审核、API/Web 自动化执行、Runner 调度、执行证据和报告分析的完整闭环。

核心链路：

```text
Requirement / Swagger
        ↓
AI 评审与用例生成
        ↓
人工审核与正式资产
        ↓
API Scenario / Web Case
        ↓
Windows Runner 确定性执行
        ↓
Evidence / AI 失败分析 / Report
```

开发遵循“深度优先、闭环优先、V1 优先”，先完成包含性能测试及配套增强能力的稳定可演示 V1，再开发 V2。

## 3. 完成度计算规则

### 3.1 状态定义

| 状态 | 判定标准 |
|---|---|
| 未开始 | 尚无实现，或仅有想法/草稿 |
| 进行中 | 已开始实现，但未达到该项验收条件 |
| 待验收 | 功能已实现，测试或演示验收尚未完成 |
| 已完成 | 满足 Definition of Done，并完成实际演示验证 |
| 阻塞 | 存在明确依赖或问题，当前无法继续 |
| 暂缓 | 不属于当前版本，按范围锁定规则暂不实施 |

### 3.2 计分方式

每个 Phase 的内部任务采用以下计分：

- 未开始：0%；
- 进行中：按已通过验收的子项计算，不使用主观估算；
- 待验收：最多计 80%；
- 已完成：100%；
- 暂缓：不计入当前版本分母。

V1 总进度计算公式：

```text
V1 总进度 = Σ（Phase 权重 × Phase 完成度）
```

功能只有同时具备数据库迁移（需要时）、后端 API、数据校验、权限、前端交互、异常状态、结构化日志、测试、文档和 Demo 验证，才可标记为“已完成”。Runner 与 AI 功能还需满足其专项完成条件。

## 10. 风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| V1 范围过大 | 周期失控、模块都不完整 | 严格按 Phase 顺序，一次只打通一条闭环 |
| AI 输出不稳定 | Case 或分析不可用 | JSON Schema、重试/fallback、原始输出留存、人工审核 |
| Runner 状态复杂 | 任务重复、状态错乱 | 明确状态机、幂等更新、心跳、Slot 和超时机制 |
| 自动化产生脏数据 | 测试环境污染 | Resource Registry、run_id 标识、LIFO Cleanup |
| Secret 泄露 | 安全风险 | 加密存储、接口不回显、日志脱敏、最小权限 |
| Web Locator 易变 | 用例不稳定 | 多 Locator、Trace、候选修复和人工确认 |
| 文档与实现偏离 | 验收失真 | 功能变更先改规格，完成后同步计划与模块文档 |
| 缺少版本协作工具 | 误改或历史难恢复 | 小步修改、关键节点手工备份、变更记录和验收清单 |
