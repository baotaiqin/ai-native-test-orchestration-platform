# V1 跨平台 Secret 与部署实施契约

2026-09-10 主控设计，尚未实施。现有 secret_cipher.py 只提供 Windows DPAPI；Linux 容器后端不能据此交付。当前 docker-compose.dev.yml 仅启动中间件，不代表完整服务器部署已完成。

## Provider 与兼容

保留 Windows 开发 DPAPI 密文及现有调用接口。增加显式选择的跨平台 Provider，使用 cryptography 的 Fernet 高层认证加密与 MultiFernet 密钥轮换能力，正式依赖必须声明并在干净环境安装验证。不得用应用 JWT 签名字符串直接充当加密密钥。库的密钥格式、验证与轮换行为依据 [cryptography 官方文档](https://cryptography.io/en/stable/fernet/)；Fernet 密文带可见生成时间，适合本项目有界的凭据/状态数据，不用于大文件加密。

跨平台 Provider 从独立只读挂载文件取得随机生成的密钥序列，第一把用于新加密，保留的旧密钥用于读取历史。密钥由库生成；无默认值、不自动生成后静默继续、不写数据库、不纳入镜像或代码。文件读取设大小与数量上限、拒绝无效/重复配置，错误仅给安全类型。生产启动前验证明确配置可用，不能启动成健康后第一次使用 Secret 才发现缺失。密钥不得出现在命令行参数、日志、公开健康检查或配置序列化中。

新密文使用独立带版本前缀。已认证的内部载荷包含格式版本、用途以及应用上下文绑定，保留现有 application_key 变化导致不可解密的语义；不自制加密算法、不在校验前输出明文。大小限制需核对既有 Secret、渠道 Key、Session 与录制快照上限，不能缩小到让合法历史数据无法读取。

Windows 可按前缀读取原 DPAPI；Linux 遇到 DPAPI 明确拒绝，不能把旧密文当作新格式、明文或无凭据继续执行。清除 ctypes.WinDLL 等 Windows 专属注解/导入在 Linux 的初始化障碍；DPAPI 库仅在真正执行 Windows Provider 时加载。

不在普通读取、服务启动或数据库迁移中自动重加密。后续跨机器转换须独立任务：先在原 Windows/原上下文中验证可读，逐条有条件更新、记安全清单，失败停止且可恢复；数据库与密钥备份分别保护，不输出明文。此设计不授权改动当前正式 DPAPI 数据或运行配置。

## 部署交付

后续独立包提供 backend 镜像、frontend 构建/nginx、服务器 Compose 和启动/备份/升级说明。Windows Runner 独立接入；不把浏览器 Runner 放入后端镜像，不改变单 Slot V1 范围。

生产配置显式给出数据库、Redis、RabbitMQ、MinIO、签名密钥、Secret Provider 与挂载路径；拒绝开发默认凭据。启动迁移、管理员初始化、应用启动分开且可观察；不能每次启动重设管理员密码。实际用户认证实现是生产发布的前置条件。

nginx SPA 路由、API/SSE代理及上传限制须与现有接口一致；仅暴露需要的入口，内部中间件不默认公开宿主所有网卡。镜像内不含 .env、验证证据、个人运行身份、数据库转储或源工作区私有文件。容器按非root运行并用必要可写目录；健康检查不打印凭据。

## 验收

- Windows 原 DPAPI 合成数据往返不变；新 Provider 的 Unicode/边界长度/随机化往返、错误密钥/篡改/格式/应用上下文/配置缺失全部安全拒绝。
- 旧密钥读取、新密钥写入、移除旧密钥后的预期拒绝；原密文不因读取而改变。
- 实际 Linux 容器导入并启动应用，真实 Secret 写入/读取和 Session/渠道使用的隔离集成验证；模拟 sys.platform 不能代替 Linux 现场。
- 公共接口、异常、日志、repr、镜像层与构建上下文不含合成密钥/明文标记；只检查自有合成数据，不读取或输出正式秘密。
- 完整服务栈隔离启动、迁移、健康、真实登录、静态页面/API/SSE、私有 Evidence 存取与重启持久化验证；精确清理独占容器/卷，不动当前正式开发服务。

Provider 先由 Backend 按明确文件包实施并回归；再由 DevOps 独立 Linux 验证和部署。不得与当前 P6-R1 共享文件写入。只有真实服务栈验收通过后，矩阵的服务器部署项才可关闭。
