# V1 本机演示系统

演示系统位于 `demo/server.py`。本地直接启动时仍只绑定 `127.0.0.1`；正式发布时通过隔离的 Demo 容器监听容器网络，并由 `DEMO_PUBLIC_URL` 指定客户和 Runner 使用的公网地址。所有账号、Token、Cookie 和资源均为该进程内的合成测试数据；容器重启即丢弃，不连接平台正式库或外部业务系统。

第一次使用并希望完成平台资产、Runner、Evidence、报告、失败修复与可选 AI 自愈的完整演示时，请按[《内置 Demo 从零到完整闭环操作手册》](./内置Demo从零到完整闭环操作手册.md)执行。

从项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m demo.server --port 8765
```

打开 `http://127.0.0.1:8765/login`，测试账号 `demo`、测试密码 `demo-pass`。这是演示目标自己的公开测试夹具，不是平台登录账号或真实 Secret。

上线后可从“AI 主演示”页面点击“访问在线 Demo”在新窗口打开。正式环境推荐使用独立 HTTPS 域名；直接暴露 `http://服务器IP:8765` 只用于受控上线验收。

| 路径 | 用途 |
|---|---|
| GET /health | 检查演示实例 |
| POST /api/login | JSON username/password；返回 data.token 并设置 HttpOnly Cookie |
| GET/POST /api/resources | Bearer或Cookie认证；列出资源或以JSON name创建 |
| DELETE /api/resources/{id} | 清理精确资源 |
| GET /api/users?q=关键词 | 查询固定合成用户 |
| GET /api/products?q=关键词 | 查询固定合成商品、价格与库存 |
| GET/POST /api/orders | 查询订单；以product_id/quantity创建并扣减库存 |
| DELETE /api/orders/{id} | 精确删除订单并恢复库存 |
| GET /api/download | 已认证的示例CSV下载 |
| POST /api/logout | 撤销当前演示会话 |
| GET /api/slow?delay_ms=500 | 可控慢请求，上限30000ms |
| GET /api/flaky?key=任意测试标识 | 同一key首次503，后续200，用于Step Retry |
| POST /control/locator | JSON changed:true/false；切换登录按钮id，保持语义标签不变 |
| POST /control/expire-sessions | 清空当前演示实例的会话，验证Session过期 |
| GET /control/state | 仅显示资源/订单数量、登录次数、定位器模式，不返回凭据 |

初始按钮为 `#login-btn`，切换后变为 `#signin-confirm`，均有 `aria-label=登录`。可先录制旧定位器，再切换页面，验证确定性失败、候选建议和人工确认新版本。

该系统仅是验收目标。真实平台的录制、AI调用、版本审核、调度、Evidence、报告和Cleanup必须通过各自正式接口完成；不能用演示目标的单元测试替代整个平台闭环。

独立目标验证：

```powershell
.\.venv\Scripts\python.exe -m pytest demo/tests -q
```

测试自动使用随机回环端口，并在结束时关闭实例。后续SQL验收会单独使用隔离MySQL；当前资源仅在内存中，不能据此声称SQL验证已通过。

可重复验收输入位于 `demo/fixtures/`：

- `资源管理需求.md`：需求导入、AI评审/生成与用例关联的合成业务需求。
- `openapi.json`：与当前目标匹配的 OpenAPI 3.0.3 文档，包含14个登录、用户、商品、订单、资源及受控故障操作和 Bearer/Cookie 认证定义，可用于 Swagger 导入和建议生成；不包含内部控制接口。
- `resources.csv`：5行资源名称样例，覆盖正常、中文、首尾空白、空字符串和纯空白，附预期HTTP状态；成功行必须按响应ID精确清理。

这些输入不代表平台相关能力已验收。样例验证会调用平台实际 OpenAPI 解析器，并对独立目标执行CSV各行和精确清理；正式平台的数据驱动、认证关联、AI、SQL、Cleanup与报告仍须各自完整验证。

“AI 主演示”初始化器使用与本机目标一致的增强版素材：20 个需求章节、上述 14 个公开 API 操作，以及覆盖需求评审、AI 测试设计、API 用例/场景、Web 录制/自愈、AI 断言、失败分析和缺陷草稿的 9 组内置 Prompt。初始化器只准备项目、环境、模型绑定、需求、API 定义、Prompt 与输出结构，不会预先创建任何 AI 评审、AI 测试设计结果、AI 用例、正式用例、场景、运行、报告或缺陷草稿；这些结果必须由演示者在平台页面中亲自生成并审核。

需求工作台首次进入不再自动选择第一条需求；用户必须先点击左侧需求树节点，右侧“AI 评审”和“AI 用例”才会解锁，从而保证 AI 上下文明确。两个页签使用醒目的 AI 功能卡，并针对 270px 窄侧栏将操作按钮纵向排列，避免中文按钮溢出。AI 评审先检查需求歧义、缺失规则、异常场景和可测试性，输出可编辑草稿；接受只冻结评审结论并保留审计，不会自动改写需求或生成用例。右侧“本需求评审记录 / 本需求设计记录”只显示当前需求；页面顶部“AI 记录”以一个居中弹窗汇总项目全部需求，并可在评审与设计记录之间切换。已结束且未被后续用例生成引用的设计记录可删除，运行中或已进入生成链的记录会被保护。

生成 API 用例时，从需求管理右侧“AI 用例”进入“AI 测试设计”：平台先创建后台记录，真实调用 `[内置 Demo] AI 测试设计` 从当前需求及子需求提取检查点并推荐 API 闭环，再由用户确认后创建用例生成任务。API 定义详情的“用此 API 发起测试设计”会先让用户选择业务需求，然后进入同一流程并强制保留当前接口；API 定义页顶部的 AI 功能只保留跨接口场景编排。AI 结果会校验真实接口编号，失败时明确降级为“规则候选”；生成完成后，页面按 `coverage:CP-xx` 标记展示需求检查点覆盖与缺口。

当前本地 Demo 已于 2026-09-12 定向重置，AI 测试设计记录、AI 用例生成任务、生成批次、AI 正式用例和对应调用记录均为 0；真实模型配置、环境、20 节点需求树、14 个 API 和 9 组内置 Prompt 均保留。需求工作台左侧长需求树为独立滚动区，便于从干净状态按章节逐步演示。
