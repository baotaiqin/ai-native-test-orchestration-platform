# 跨平台 Secret Provider 配置说明

## 适用范围与状态

本说明覆盖 V1-D2/r1 的应用层 Secret Provider 配置。当前状态是代码已实现、Windows DPAPI 与静态基本检查通过；Fernet 依赖安装后的真实往返、Linux 容器和正式密钥挂载仍待集中验收。本文不授权读取、转换或覆盖任何现有正式密文，也不包含可复用密钥。

## 配置项

应用继续使用 `encrypt_secret(plaintext, application_key)` 与 `decrypt_secret(ciphertext, application_key)`，业务调用方不需要改变参数。

- `APP_SECRET_PROVIDER`：允许 `dpapi` 或 `fernet`，不区分大小写。Windows 开发环境缺省为 `dpapi`；生产环境必须显式设置。
- `APP_SECRET_FERNET_KEY_FILE`：Fernet 密钥序列文件路径。选择 `fernet` 时必须配置为独立挂载文件；推荐生产环境使用固定绝对路径，例如 `/run/secrets/ai-test-fernet.keys`。
- `APP_SECRET_KEY`：仍用于 A1 认证签名及 Secret 的应用上下文绑定。它不是 Fernet 加密密钥，禁止据此派生、复制或替代 Fernet 文件内容。

应用 lifespan 会先验证所选 Provider，再启动后台协调器并报告应用已启动。Fernet 文件缺失、不可读、格式错误、重复、超限或依赖不可用都会安全拒绝启动。错误消息不包含文件内容、密钥或明文。

## 密文兼容与边界

- 历史 Windows 密文前缀保持 `dpapi:v1:`。只有 Windows 能读取；Linux 明确拒绝，不会将其当作明文或其他格式继续运行。
- 新密文前缀为 `fernet:v1:`。Fernet 认证载荷内含独立格式版本、固定用途和 `application_key` 上下文摘要；密钥错误、密文篡改或上下文变化都会拒绝解密。
- 解密按密文前缀分派，因此 Windows 切换到 Fernet 后仍可读取原 DPAPI 密文；普通读取不会自动重加密、改写数据库或转换格式。
- 明文上限为 1,000,000 UTF-8 字节，覆盖现有 10,000 字符 Secret、4,096 字符模型渠道 Key、512 KiB 录制 DOM 和 1,000,000 字节 Session Storage State。载荷与密文另有考虑 JSON 转义膨胀的有界上限。

## 密钥文件格式

密钥文件必须满足以下全部条件：

1. ASCII 文本，总大小不超过 4,096 字节。
2. 一至八行，每行恰好一个由 `cryptography.fernet.Fernet.generate_key()` 生成的 URL-safe Base64 32 字节密钥。
3. 第一行是当前写入密钥；后续行仅用于读取历史密文。
4. 不允许重复密钥、空行、注释、前后空白、BOM 或其他字段。

密钥必须由受控的离线管理流程直接调用库的 `Fernet.generate_key()` 生成，并原子写入权限受限的目标文件；生成流程不得把结果打印到控制台、放进命令行参数、Shell 历史、工单、日志、镜像层或源代码。本文刻意不提供可直接复制的密钥或会把密钥输出到终端的命令。

## 挂载与权限原则

- 密钥文件独立于 `.env`、JWT 签名配置、数据库备份、镜像和源码保存。
- 容器以只读文件挂载，仅应用运行身份可读；目录不可列给无关身份，应用不拥有修改权限。
- 编排层只注入 Provider 名与文件路径，不把密钥内容放入环境变量、健康检查或启动参数。
- 文件轮换应采用同文件系统内的安全原子替换，并重启应用，让启动检查验证完整配置；不要在写入半个文件时热切换。
- 密钥备份与数据库备份分开加密、分开授权并定期验证恢复；备份清单只记录版本/保管位置标识，不记录密钥内容。

## 轮换步骤原则

1. 在受控环境生成一把新密钥，将其放到文件第一行，原第一行及仍需读取的旧密钥依次后移。
2. 原子替换只读挂载源并重启应用；启动检查通过后，新写入使用第一把密钥，读取会按顺序尝试保留密钥。
3. 观察期内保留旧密钥。读取旧密文不会修改其内容，也不会自动轮换。
4. 只有独立的跨机器密文转换任务完成、数据库备份可恢复且旧密文清单归零后，才允许移除旧密钥。
5. 移除旧密钥后，对仅由该密钥加密的历史密文应按设计安全拒绝；不得回退到明文或默认密钥。
