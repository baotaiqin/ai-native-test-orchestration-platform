# V1 服务器部署运行说明

所有服务容器均显式使用 UTC；MySQL 同时固定 `default-time-zone=+00:00`，Backend 的
PyMySQL 平台连接也在建连时执行 `SET time_zone = '+00:00'`。因此旧表的
`server_default=NOW()` 与新代码的 UTC-naive `DATETIME` 写入保持同一时间基准；这不会
猜测或批量改写来源不明的历史本地时间。

`deploy/server/compose.yml` 用于有源码构建场景；`deploy/server/compose.release.yml` 用于本地构建镜像后、服务器不保存源码的发布场景。两者都组装 Frontend、Backend、在线 Demo、MySQL、Redis、RabbitMQ、MinIO 和 Prometheus。Windows Runner 仍在服务器外独立运行。本说明只是部署交付，不代表已完成 Linux/镜像/真实服务联调。完整手动步骤见[《本地构建镜像与Ubuntu服务器部署手册》](./本地构建镜像与Ubuntu服务器部署手册.md)。

## 首次准备

1. 把 `deploy/server/.env.server.example` 复制到仓库外的受保护路径，填写所有空值。镜像在现场构建前应锁定经审核的不可变 tag 或 digest；不使用 `latest`。
2. 独立生成 JWT 签名秘钥 `APP_SECRET_KEY` 和 Fernet 密钥文件，两者不得复用。Fernet 文件只授权服务运行账号读取，通过 `APP_SECRET_FERNET_KEY_FILE_HOST` 挂载到容器内的 `/run/secrets/app-fernet.key`，只读。
3. `APP_DATABASE_URL`、`APP_REDIS_URL`、`APP_RABBITMQ_URL` 中的账号或密码必须与同一环境文件里的 MySQL、Redis、RabbitMQ 配置一致，对特殊字符做 URL 编码。不得使用项目的开发默认密码。
4. `APP_CORS_ORIGINS` 填对外访问的精确 origin（如 `https://test.example.com`），不使用通配符。
5. `DEMO_PUBLIC_URL` 填客户和 Windows Runner 都能访问的 Demo 地址。正式环境使用独立 HTTPS 域名；服务器 Compose 会显式启用管理员专属的 AI 主演示初始化接口，页面按钮和自动初始化环境会共同使用该地址。

## 网络暴露

默认前端入口和 RabbitMQ 5672 仍只绑定 `127.0.0.1`；在线 Demo 默认发布到 `0.0.0.0:8765` 以便首次公网验收。正式对客时应把 `DEMO_BIND_ADDRESS` 改为 `127.0.0.1`，由独立 HTTPS 域名的反向代理转发。远程 Windows Runner 使用前，把 `RUNNER_BIND_ADDRESS` 设为服务器的受管内网 IP，并在防火墙中只允许 Runner 网段。Runner 的 Backend URL 指向前端入口（nginx 代理 `/api/v1`），队列 URL 指向 5672。MySQL、Redis、MinIO 和 RabbitMQ 管理端口不对宿主机发布。

## 启动与变更步骤

必须把数据库备份、迁移、管理员初始化和应用启动分开执行：

1. 先备份 MySQL 持久卷及 Fernet 密钥文件，保留当前应用镜像 digest 和数据库 revision。
2. 在已复制的备份上演练 `alembic upgrade head`，审查结果后再对正式环境显式执行。Compose 不会自动迁移。
3. 仅首次建立管理员时手工执行 `python -m app.modules.auth.bootstrap --confirm-bootstrap`。该命令保留历史 `dev-admin` ID，不得放入每次启动流程。
4. 然后启动 Backend 和 Frontend。`/health` 只说明 Backend 进程可回应，不代表 MySQL/Redis/RabbitMQ/MinIO 或 AI Provider 就绪。

参考命令（必须显式传入仓库外环境文件）：

```text
docker compose --env-file <protected-env-file> -f deploy/server/compose.yml build
docker compose --env-file <protected-env-file> -f deploy/server/compose.yml run --rm backend alembic upgrade head
docker compose --env-file <protected-env-file> -f deploy/server/compose.yml run --rm backend python -m app.modules.auth.bootstrap --confirm-bootstrap
docker compose --env-file <protected-env-file> -f deploy/server/compose.yml up -d
```

回退时先停止写入，优先恢复与旧镜像对应的数据库备份；不在未验证 downgrade 的正式库盲目执行 Alembic 回退。项目当前尚未上线、没有正式生产库；截至 2026-09-13，代码 head 与本地开发库均为 `20260913_0077`。首次上线必须使用独立空生产库，并以发布镜像内 `alembic heads` 的实际输出重新核对迁移 head。
