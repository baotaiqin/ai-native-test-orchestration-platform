## 实现摘要

### Test Case 编辑

- 新建 API Case 默认 `max_retries=0`，只提供数值 `0/1` 选择；文案明确 `1` 是“首次执行之外最多额外一次”，总尝试最多两次。
- 不再使用 `Number`、截断或 clamp 修正重试次数。字符串、布尔、负数和大于 1 的值均不能保存为新 Case/新版本。
- 历史 2/3 或畸形值原样载入，并以禁用的历史选项展示；保存按钮保持禁用，必须由用户显式选择 0 或 1。
- 打开详情、打开新版本编辑和取消均不写入；创建合法新版本不会改写旧版本。
- 手工保存错误改为优先展示后端返回的 `API_STEP_RETRY_LIMIT_EXCEEDED` 实际消息。
- 原有 `retry_on`、`backoff_ms`、运行预算说明与历史读取类型保持兼容。

### AI 建议审核

- `formResult()` 改为从当前有效建议内容的独立 JSON 深拷贝出发，只覆盖界面上明确编辑的字段。
- 实测完整保留 `request`（除用户显式修正的 `max_retries`）、`pre_actions`、`post_actions`、`extractors`、`data_source`、`assertions`、`cleanup` 及未知 `vendor_extension`。
- 单条 Accept 前校验 0/1；Reject 仍允许处理旧策略草稿。批量 Accept 在发送前检查全部勾选草稿，任一非法则整个请求不发送；批量 Reject 不受此门禁影响。
- 保存→接受在点击时快照锁定建议 ID、需求 ID、项目 ID、编辑内容和说明。保存期间切换建议，后续决定仍只发给原 ID；切换需求/项目上下文则只允许原编辑保存完成，不再发送 Accept。
- 引入面板生命周期/上下文代际：需求切换（含 A→B→A）与组件卸载都会使旧操作失效；迟到的 PATCH/Decision、成功或错误消息及刷新均不能污染新页面。
- Reject 只快照建议身份、项目、需求和备注，不读取或校验未保存编辑内容，也不发送 PATCH；因此非法 steps/test-data JSON 和非法旧重试值均不阻断拒绝。
- 增加忙碌态和同步防重复入口；重复点击不产生重复 PATCH/Decision。
- 单条、批量及保存错误均优先提取并展示后端重试上限错误，不再被“可能已经完成决策”覆盖。

### Run Center

- 只在 API Case 新运行入口读取所选 Case 的当前版本；历史 `max_retries=2/3` 时客户端阻断新 Run，并引导前往测试用例显式创建 0/1 新版本。
- 当前版本详情读取中、读取失败或不存在时保持关闭式门禁；合法 0/1 才生成新运行 payload。
- 后端 `/runs/validate` 仍是权威门禁；Create 外层 `RUN_VALIDATION_FAILED` 会递归提取嵌套 `API_STEP_RETRY_LIMIT_EXCEEDED` issue。
- 未改变旧 Run 列表、详情、取消或完成结果；未改 Scenario、Web、Healing、FailureAnalysis 和 SSE 状态机。

结果：退出码 0；Vite 共转换 1764 个模块，产物写入独立目录 `.codex-validation/v1-t3/dist`。仅有既存的大 chunk 建议和第三方 PURE 注释位置警告，无构建失败。

### 合成真实 Chrome

命令：

```powershell
.\.venv\Scripts\python.exe frontend/tests/v1_t3_retry_policy_playwright.py --dist .codex-validation/v1-t3/dist --out .codex-validation/v1-t3
```

结果：退出码 0；Chrome channel，18 项检查全部通过，`page_errors=0`、`unexpected_console_errors=0`。覆盖：

1. 新建打开/取消零写入；新建 0 和 1 的请求值均为严格数值。
2. 历史 3 打开/取消零写入；3、字符串 `"1"`、布尔 `true`、负数 `-1` 均原样可读且不能保存。
3. 显式把历史 3 改为 1 后只创建新版本，旧夹具仍为 3。
4. 手工保存后端 409 原文展示。
5. 建议完整载荷深比较：所有未编辑配置和未知扩展字段保持一致，仅 `max_retries: 3 -> 1`。
6. 延迟保存时切换建议仍只决定原 ID；重复点击只有一次 PATCH 和一次 Decision。
7. 延迟保存时切换需求只保存原编辑，不发送 Accept。
8. 批量 Accept 非法集合零请求；全合法集合单请求；批量与单条 Reject 可处理旧策略草稿。
9. 单条 Accept 后端 409 原文展示。
10. 延迟 PATCH 期间需求 A→B→A 后旧 Accept 失效，无迟到 Decision、成功消息或刷新。
11. 通过真实 RouterLink 离开并卸载组件后，迟到 PATCH 不再触发 Decision、消息或刷新。
12. 卸载后的合成 409 静默处理，不在项目页显示旧操作错误。
13. 未保存的非法 steps JSON 与非法 test-data JSON 均不阻断 Reject，且 Reject 不发送 PATCH。
14. Run Center 历史 3 在 Validate/Create 前阻断；合法 1 会调用 Validate，Create 的嵌套错误展示内层重试 issue。
15. 历史完成 Run 可读，历史 CREATED Run 可取消。

受控写入计数：Test Case 4 次（两个新建、一个合法版本、一个合成 409 请求）；建议 PATCH 6 次、单条 Decision 5 次、批量 2 次；Run Validate 1 次、合成 Run Create 1 次、历史 Run Cancel 1 次。全部仅命中 Playwright 路由拦截器。

验证脚本在 `finally` 中关闭 Chrome context/browser，并关闭回环 `ThreadingHTTPServer`、等待服务线程退出；命令进程已正常退出。未启动或停止正式服务。
