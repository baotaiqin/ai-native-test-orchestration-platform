## 执行语义

保存计划时固定每个目标的版本。启动时先对全部启用项复用既有 Run 校验，任一项不通过则整批不创建；全部通过后，每项创建独立子 Run 并通过既有 RabbitMQ/Runner 链路投递。父级计划运行不另造执行引擎，只聚合子 Run 状态，因此取消、总超时、证据和报告仍由既有 Run 负责。

计划变量最多 50 项、64KB，只允许规范变量名并拒绝敏感命名与系统保留字段。变量被固化到子 Run，API、Scenario 和 Web 三类执行计划均可读取；Secret 仍只能走现有托管引用机制。

## 明确边界

当前策略固定为 `PARALLEL + CONTINUE`。串行 Stop-on-failure、Schedule、CI/CD Trigger 和通知不在本批伪实现：Schedule/CI/CD 后续只负责创建同一 Test Plan Run，通知再订阅其聚合终态。真实多 Runner 压力、浏览器视觉和独立迁移往返保留到《集中验收待办》。

按当时权重，性能测试主流程计 45%，Test Plan 主流程计 15%，本轮 V1 增强能力合并进度暂记 **60%**。剩余为 Scheduler、CI/CD API/Webhook、AI Performance Analysis、Prometheus 与 Scenario Flow Editor。
