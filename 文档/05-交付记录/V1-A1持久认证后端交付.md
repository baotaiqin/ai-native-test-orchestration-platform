# V1-A1/r1 持久认证与用户管理后端交付

## 交付状态

已实现，基本检查通过，待集中验收。本轮未执行 Backend 全量、完整 JWT/泄漏矩阵、两连接 MySQL 竞态、迁移往返、正式 bootstrap、服务重启、浏览器矩阵或前端联调。

## 已实现

- 新增持久化 `User`、`AuthSession` 与管理员串行保护记录。用户保存稳定字符串 ID、规范化唯一用户名、Argon2id 密码 Hash、`ACTIVE/DISABLED`、平台 `ADMIN/USER`、`auth_version` 和 UTC 时间；Session 只保存随机 `sid` 的 SHA-256 摘要，不保存 JWT 或原始 `sid`。
- 登录使用 Argon2id 高层接口并支持参数升级；依赖明确固定为 `argon2-cffi>=25.1,<26.0` 与 `PyJWT>=2.13,<3.0`。错误密码与不存在用户返回统一口径，并用固定合成 Hash 保持验证路径。
- JWT 仅接受 HS256，要求并校验 `sub/sid/av/iat/exp/iss/aud` 及类型、大小与时序。请求使用同一数据库依赖核对 User、Session、撤销状态、到期时间、签发/到期绑定和 `auth_version`；权限角色始终取当前数据库，不信任 Token 角色。
- 保持 `POST /api/v1/auth/login` 与 `GET /api/v1/auth/me` 响应兼容；新增当前 Session 登出和本人改密。改密更新 Argon2id Hash、递增版本并撤销该用户全部 Session。
- 新增管理员用户分页查询、创建及显示名/平台角色/状态更新。角色或状态改变会递增版本并撤销旧 Session；普通用户不能调用用户管理接口。
- 最后可用管理员保护采用单行 `SELECT ... FOR UPDATE` 串行门闩，并在门闩后使用当前锁定读取得可用管理员集合，避免 MySQL REPEATABLE READ 旧快照绕过零管理员约束。两连接 MySQL 实测留待集中验收。
- 项目成员新增和改角色前校验目标持久用户存在且为 `ACTIVE`；不为历史成员增加外键、不改写历史 ID。
- 新增显式 CLI `python -m app.modules.auth.bootstrap --confirm-bootstrap`。它从现有配置在内存读取账号密码，只创建稳定 ID `dev-admin`；重复执行不覆盖密码/角色，冲突安全拒绝，应用启动不自动执行。
- 新增迁移 `20260910_0041`，父版本固定为 `20260910_0040`。迁移仅建结构与管理员串行门闩，不读取密码或创建默认用户。
- 新增统一真实认证测试辅助，并接入所有仍调用 `/auth/login` 的独立 SQLite 模块夹具；没有通过全局伪造 ADMIN 绕过新认证。项目权限专项改为真实普通用户登录，并覆盖停用用户不可加入项目。

## 接口冻结

- 兼容：`POST /api/v1/auth/login -> TokenResponse`、`GET /api/v1/auth/me -> CurrentUser`。
- 新增：`POST /api/v1/auth/logout`。
- 新增：`POST /api/v1/auth/change-password`。
- 新增：有界 `GET /api/v1/auth/users?page&page_size`、`POST /api/v1/auth/users`、`PATCH /api/v1/auth/users/{user_id}`。
- 用户公开响应不包含密码或 Hash；用户名创建后不可修改；不开放公共注册、删除用户、SSO 或密码重置。
