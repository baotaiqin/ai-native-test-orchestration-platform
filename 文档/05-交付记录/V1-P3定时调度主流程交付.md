# V1-P3 定时调度主流程交付

## 交付结论

Test Plan 定时调度主流程已完成：项目成员可创建 Daily、Weekly 或标准 5 段 Cron 任务，按 IANA 时区预览和计算下次时间；后台调度器到点后只创建并投递既有 Test Plan Run，测试仍由 Runner 执行。

## 已实现范围

- 项目级定时任务创建、编辑、启停、归档/恢复及最近 100 条触发历史。
- Daily、Weekly、Cron（分、时、日、月、周）三种表达方式；Cron 支持 `*`、列表、范围和步长，周日接受 0 或 7。
- IANA 时区与夏令时安全换算；不存在的本地时间跳过，重复本地时间只触发一次。
- 持久化 `next_run_at`，扫描器只认领到期项并提前计算下一次；错过多个周期时合并为一次，不产生补跑风暴。
- `schedule_id + scheduled_for_at` 唯一触发账本、行锁与短事务，避免并发扫描重复创建。
- 到点前重新校验项目、创建人、Test Plan、Environment、Runner、Capability 与 Slot；失败原因落入触发历史，修复后可以手动重试。
- Test Plan Run 增加 `MANUAL / SCHEDULE / API` 来源和 Schedule 关联；子 Run 继续使用既有 `SYSTEM` 触发语义。
- FastAPI lifespan 启停独立调度线程；扫描间隔可通过 `APP_SCHEDULE_SCAN_*` 配置，测试进程默认关闭真实后台扫描。
- 项目工作区新增“定时任务”页面，包含调度配置、未来五次预览、下次/上次时间、触发历史、错误与重试入口。

## 明确边界

- 本包不实现 CI/CD Token、外部 Webhook、Email 或站内通知；这些属于后续 CI/CD 与通知包。
- 调度触发成功表示 Test Plan Run 已创建并投递，不代表测试结果成功；最终结果仍以 Test Plan Run 聚合状态为准。
- 默认前端 `dist` 仍由运行中进程占用，本次未停止或重启现有服务，只在隔离目录完成生产构建。
