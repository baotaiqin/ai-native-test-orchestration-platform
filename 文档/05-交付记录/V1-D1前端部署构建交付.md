# V1-D1/r1 前端部署构建交付

## 结论

V1-D1/r1 已实现，静态基本检查通过，真实镜像与服务器行为待集中验收。本包没有启动 Docker、拉取镜像、执行真实部署或修改现有开发服务，也没有修改 `frontend`、`backend` 应用源码和包文件。

## 已实现

- `deploy/server/frontend.Dockerfile`：项目根上下文、`package-lock.json` + `npm ci`、现有 `npm run build`、Vite 多阶段构建、非 root nginx 运行时、8080 端口和 `/healthz` 容器健康检查。
- `deploy/server/frontend.Dockerfile.dockerignore`：Dockerfile 专用的默认拒绝白名单，仅放行构建所需文件；`.env`、`.codex-validation`、Git/IDE 配置、`node_modules`、既有 `dist` 等保持排除。
- `deploy/server/frontend-nginx.conf`：SPA 回退、哈希资产长缓存、`index.html` 禁止长期缓存、`/api/v1` 原路径代理至 `backend:8000`、API 错误不回退 SPA、SSE 禁用缓冲/缓存并使用一小时读写超时。
- nginx 的 PID、请求体与各类临时路径均落在 `/tmp/nginx`；运行时 UID/GID 为 101，不在启动时写 `/etc`。
- `client_max_body_size 21m` 为后端最大 20 MiB 文件及 multipart 边界/最多 64 KiB 元数据保留入口信封空间，最终类型大小仍由后端校验。
- `deploy/server/frontend-entrypoint.sh`：只创建显式临时目录、确认配置和构建产物可读，然后以前台模式 `exec nginx`。
- `文档/01-使用指南/服务器前端部署说明.md`：记录精确根上下文构建命令、内部 DNS/端口、TLS 边界、Windows Runner 独立性和集中验收缺口。

## 待集中验收

以下事项尚未验证，不应标记为已验收：

1. 拉取基础镜像并完成真实 `docker build`，确认镜像标签、构建依赖和 healthcheck 工具可用。
2. 在构建出的镜像内执行 `nginx -t`，并验证非 root 启动、只读配置、PID/缓存/临时目录、停止信号与重启行为。
3. 实测 SPA 深链接、静态 404、资产缓存头、`index.html` 无长期缓存、API 4xx/5xx 不回退页面。
4. 实测 `/api/v1/runs/{run_id}/events/stream` 长连接、断线重连、`Last-Event-ID`、首包延迟和中间代理无缓冲。
5. 实测接近 20 MiB 的 XLSX/Web Evidence multipart 请求及 413/后端类型上限边界。
6. 验证正式容器网络中的 `backend:8000` DNS、外层 TLS 终止、转发头、日志、资源限制、漏洞扫描、回滚和服务编排。
7. 验证 Windows Runner 仍独立部署，并通过正式后端入口通信；本包不包含 Runner 镜像化或服务化。

## 范围说明

本交付只是服务器前端部署基础，不包含后端部署、认证/Secret Provider、现有 `deploy/docker-compose.dev.yml` 修改或正式环境联调，也不代表 V1 已完成真实部署。上述待验项应由主控纳入后续集中验收。
