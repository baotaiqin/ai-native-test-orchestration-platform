## 修改文件

- `backend/app/modules/web_cases/schemas.py`：新增 `ASSERT_HIDDEN`、`ASSERT_CLICKABLE`。两者只接受 `type`、必填 `locator`、严格整数 `timeout_ms`；禁止 `expected` 和额外字段，超时范围仍为 100..600000。
- `backend/app/modules/runs/service.py`：允许已启动节点按 Runner 实际结果从 `RUNNING` 收口为 `SKIPPED`，避免把失败后未执行的断言补成 `PASS`。
- `backend/tests/test_web_cases.py`：将两种断言纳入既有严格 DSL、超时、Locator、持久化、锁版本、计划、completion 与报告契约矩阵。
- `backend/tests/test_runs.py`：新增隔离真实 HTTP 闭环，并使用 Runner 最终客户端解析器验证后端计划。

## 接口与兼容性

- WebCase DSL 新增 `ASSERT_HIDDEN`、`ASSERT_CLICKABLE`。
- 执行计划保持 `schema_version=1`，断言仍固定为 `type/locator/expected/timeout_ms` 四字段；两个新类型的 `expected` 显式为 `null`。
- Run 创建后即锁定批准的 `WebCaseVersion`；即使随后产生新 current 草稿，旧 Run 的 dispatch、claim 与计划仍使用原版本。
- 直接 Locator、精确 `ElementVersion` 候选和 Environment 模板上下文均保持原路径。
- completion 仍要求 trace 完整且只能覆盖固定节点；陌生节点拒绝。报告保留 Runner 实际 `FAILED/SKIPPED`，不伪造未执行断言为成功。
- 未修改报告 API、需求快照契约、Runner 协议、模型或迁移。
