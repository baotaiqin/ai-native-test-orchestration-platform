# V1-A2 持久认证前端 r2 交付

## 交付结论

- 任务包：`V1-A2/r2`。
- 状态：跨窗口认证刷新循环已修复，针对性合成检查与类型检查通过；浏览器集中验收待主控统一执行。
- 阻塞：无。

## 修复内容

1. 将明确登录或 `/auth/me` 返回不同账号的身份提交，与同一账号的资料刷新分开处理。明确身份切换仍生成新 epoch，保持同 token 文本下的 A-B-A 隔离。
2. 同一账号且资料完全一致时，`/auth/me` 只把当前身份标记为已验证，不再生成 epoch，也不再写入 `localStorage`，从源头消除 `storage -> /auth/me -> storage` 回声循环。
3. 同一账号的显示名、角色等真实资料变化保持原 epoch，但会使当前窗口的旧认证写操作失效，并只持久化一次新资料。对端窗口收到 storage 事件后同样使旧操作失效、拉取权威资料；由于资料已一致，不会再次写回。
4. 新增两个隔离运行时共享存储与 StorageEvent 传播的合成检查，覆盖有限刷新后收敛、角色变化传播、旧特权操作失效，以及相同 token 文本的迟到 A 登录不能覆盖 B 身份。
5. 本轮未修改 `frontend/src/api/http.ts`；其既有 storage generation、token 与 epoch 的迟到 401 防护保持不变。
