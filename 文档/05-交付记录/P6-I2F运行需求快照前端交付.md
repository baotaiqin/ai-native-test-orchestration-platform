# P6-I2F 运行需求快照前端交付

## 交付结论

- 任务包：`P6-I2F/r1`。

- 本轮只修改任务包授权的前端报告类型、API、详情页及独占证据/交付文件。

## 实现内容

1. 对齐冻结后端契约：补充四种捕获状态、需求版本绑定、资产版本绑定、`ReportCase.requirement_capture`、`ReportDetail.requirement_sources` 与独立分页查询类型。
2. 增加固定内部接口 `GET /reports/{run_id}/requirement-sources`；分页和 CaseRun 过滤始终重新构造已知路径，不读取或跟随服务端 `continuation_path`。
3. 报告详情新增“运行创建时需求来源”：
   - 明确区分“已记录来源”“创建时未关联需求”“历史运行未记录，无法判断当时关联”“此目标类型尚不支持来源捕获”；后两种不会表述为无需求。
   - 展示捕获时的需求代码、标题、类型、状态、精确/未知需求版本、实际执行目标及版本、关系资产版本绑定、关系类型、来源、置信度、原始/替代关系 ID 与审计时间。
   - 展开区保留内容哈希、来源类型、完整 ID、绑定说明、创建人和历史范围等捕获元数据；不查询当前需求或当前关联补造历史。
   - `LEGACY_UNKNOWN` 时间保持后端原字符串并标注“历史时间，时区未记录”；UTC 时间明确转换为北京时间显示。
4. 固定版本深链保持类型隔离：需求只在精确版本存在时跳转；`TEST_CASE` 与 `WEB_CASE` 使用不同路由和查询键，即使数字 ID 相同也不会混淆。
5. 独立来源查询具备 Run、CaseRun 过滤、身份指纹、详情对象、请求序列和组件卸载保护，可拒绝切换、A-B-A 或卸载后的迟到响应。失败态显示错误和重试，不伪装为空状态。
6. 完整报告下载继续由服务端汇总，未使用当前页面分页内容拼装导出文件。
