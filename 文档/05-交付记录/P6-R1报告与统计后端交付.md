## r1 审查拒绝与 r2 闭环

r1 的功能、权限、脱敏、全分页和查询增长复验均通过，但主控新增的 6 项独立输入边界探针发现：`created_from=0001-01-01`、`created_to=9999-12-31` 会在上海日界换算或结束日期加一天时触发 `OverflowError`；`page=2**80` 会在报告目录及 Case/Step/Evidence 的 SQL OFFSET 绑定阶段触发 SQLite INTEGER `OverflowError`。因此 r1 未通过主控验收，原失败证据保留在 `.codex-validation/p6-report-r1-controller-review.txt`，原 `.codex-validation/p6-r1/validation.txt` 未覆盖或改写。

r2 在请求模型层增加可见的精确边界，超界直接返回 422，不进入业务查询；没有捕获所有异常、没有把错误伪装成空成功，也没有截断或 clamp 用户输入：

- 所有用于数据库查询的 `project_id`、`environment_id`、`case_run_id`、`step_run_id` 限制为 `1..2147483647`，对应项目 SQL `INTEGER` 的正有符号 32 位范围；Dashboard `project_id` 使用同一范围。
- `page` 限制为 `1..2147483647`，`page_size` 限制为 `1..100`。最大 OFFSET 为 `(2147483647-1)*100=214748364600`，仍在 SQL 参数的有符号 64 位安全范围；请求不会被静默改写。
- `created_from/created_to` 限制为 `1000-01-02..9999-12-30`。这是上海本地日零点换算 UTC、`created_to+1 day` 和 MySQL DATETIME 三者共同安全的最宽边界；`created_to` 仍使用次日零点排他的查询方式，正常单日完整包含到当日末尾。
- OpenAPI 对整数暴露标准 `maximum/minimum`，对日期暴露描述及 `x-minimum/x-maximum`；新增测试同时覆盖非法极值、相邻合法边界、正常日期和稳定分页。

## 接口清单

| 方法与路径 | 用途 | 关键边界 |
|---|---|---|
| `GET /api/v1/reports?project_id=...` | 项目内 Run 报告目录 | 项目授权后查询；支持类型、状态、环境、上海创建日期和分页筛选 |
| `GET /api/v1/reports/{run_id}` | 有界报告详情首屏 | 返回摘要、锁定版本引用、Case/Step/Evidence 首屏、AI 审计安全引用 |
| `GET /api/v1/reports/{run_id}/cases` | CaseRun 分页 | `page_size` 1～100；类型化三类执行结果 |
| `GET /api/v1/reports/{run_id}/steps` | StepRun 分页 | 可按 `case_run_id` 限定；稳定顺序 |
| `GET /api/v1/reports/{run_id}/evidence` | Evidence 元数据分页 | 可按 Case/Step 限定；只给受保护下载路径 |
| `GET /api/v1/dashboard` | 可见 ACTIVE 项目聚合 | 可用 `project_id` 进一步限定；不可见或归档项目统一 404 |

所有 Query 模型均拒绝额外参数。报告列表的 `project_id` 必填；数据库 ID、页码、页大小和日期均遵循上述 OpenAPI 边界，日期起点不得晚于终点。不存在与无权限的合法范围 ID 仍复用项目授权语义返回 404，避免通过差异错误或全局总数泄露其他项目。

## 报告数据口径

### 历史身份与版本

- `run_id`、运行类型、状态、时间、原始 Run 计数、目标 ID/版本 ID 以及执行结果来自历史记录。
- API、Web、Scenario 的 `target.version_id` 一律来自 Run/CaseRun 锁定引用，`version_basis=LOCKED_BY_RUN`；不会以资产 `current_version_id` 替换历史版本。
- `version_no` 只从该锁定版本记录读取；版本缺失或归属不匹配时返回 `version_available=false`，不猜测内容。
- 资产名、编码、状态如可用，明确标记 `target.asset_metadata_basis=CURRENT`；项目、环境和 Runner 引用使用 `metadata_basis=CURRENT`。这些都是当前元数据，不声称是运行时快照，并与 `version_basis=LOCKED_BY_RUN` 的历史锁定版本明确区分。
- `definition_exposure=REFERENCE_ONLY`：本接口不返回 API/Web/Scenario 版本定义正文，因此也不会从当前版本重建旧定义或带出 StorageState、凭据等字段。
- 已归档项目仍可在原项目授权范围内读取历史报告，但报告接口没有执行或修改能力。

### 状态、计数、成功率和时长

- `recorded_counts` 原样返回 Run 的 `total/pass_count/fail_count/review_count/timeout_count`，并标记 `source=RUN_RECORD`。
- `case_status_counts` 由 CaseRun 按真实状态分组，单列 CREATED、ASSIGNED、RUNNING、CANCELLING、SUCCESS、FAILED、REVIEW、TIMEOUT、CANCELLED、SKIPPED；`unfinished` 是前四个未完成状态之和。
- 报告用例通过率固定为 `SUCCESS / (SUCCESS + FAILED + REVIEW + TIMEOUT)`；返回分子、分母和 0～1 比例。SKIPPED、CANCELLED、未完成不进入分母，分母为 0 时 `value=null`。
- Run/Case/Result/Step 的状态分别保持各表事实，不做推断覆盖。因此 Web 平台 `FAILED / WEB_EVIDENCE_ERROR` 即使所有 StepRun 与已存 Web Result 为 SUCCESS，也仍保持原矛盾审计事实。
- `started_at` 缺失时 duration 为 `UNAVAILABLE/null`；有 `ended_at` 时为 `COMPLETED`；仍在运行时用响应生成时刻计算 `OBSERVED`，并返回 `observed_at`。

### 执行结果与缺失降级

CaseRun 结果按目标类型读取 `run_api_execution_results`、`run_scenario_execution_results`、`run_web_execution_results`，不从 Step 状态重算：

- API 只返回已持久化的安全 `response_summary` 与 `assertion_results`；
- Scenario/Web 只返回已持久化的类型化 `traces`；
- 没有结果记录时，结果整体为 `NOT_RECORDED`；
- 实际请求正文与提取结果当前没有历史持久化来源，固定明确为 `NOT_RECORDED`，不会读取当前环境变量、Secret 或当前资产配置补造；
- 类型没有相应字段时使用 `NOT_APPLICABLE`，与“应有但未记录”区分。

所有任意文本和 JSON 值均经过 L1/r2 的 `redact_text` / `redact_value` 有界副本脱敏，数据库原值不变。响应采用显式 Pydantic 字段映射，没有 ORM 全列序列化。

### Evidence 与 AI 审计

- Evidence 只返回 ID、关联 Run/Case/Step、类型、文件名、MIME、大小、SHA256、既有公开元数据和创建时间。
- 下载路径固定为相对的 `/api/v1/evidence/{artifact_id}/download`，继续走原 Evidence 鉴权、完整性与下载逻辑；报告列表不读 MinIO 正文，不返回 bucket/key 或未授权地址。
- 详情仅给已有 WebFailureAnalysis/WebHealingProposal 的数量、最新一条安全摘要和既有运行子资源路径；`raw_ai_content_exposed=false`，不返回原始 prompt/response。
- Case、Step、Evidence 详情首屏分别最多 20/50/50 条。每页返回 `has_more`、`next_page`、`continuation_path`，不会静默截断。
- 列表引用按类型批量加载、Case 状态一次分组查询；Case 页最多对三类结果表各做一次批量查询。没有逐条 Case/Step/Evidence 或 MinIO 查询造成的 N+1。

## Dashboard 数据口径

- 默认范围是当前用户可见且状态为 ACTIVE 的项目；`project_id` 只能在此集合内进一步限定。归档项目不进入任何 Dashboard 统计。
- API Case：非 ARCHIVED 的 `test_cases` 且 `case_type=API`；Web Case：非 ARCHIVED 的 `web_cases`；`case_total=api_cases+web_cases`。Scenario 独立统计，不混入 Case 总数。
- “今日”按 `Asia/Shanghai` 自然日确定，再转换成 `[start_utc, end_utc_exclusive)` 查询 Run 的 `created_at`。接口返回 UTC 起止与字段口径，并以午夜前 1 秒、起点、终点前 1 秒、终点四个边界验证。
- 今日 Run 成功率为 `SUCCESS / (SUCCESS + FAILED + TIMEOUT)`；CANCELLED 单列，CREATED/ASSIGNED/RUNNING/CANCELLING 归入 `unfinished`，均不进入分母；分母为 0 时 `value=null`。
- 待审核只统计四类真实 `DRAFT`：RequirementReview、AiCaseSuggestion、WebRecordingAiSuggestion、WebHealingProposal。查询按项目和可用父资产过滤；录制/Healing 的生成中占位（无 AI call、无完整提议）及已确认录制不计，已归档/停用父资产不计，四类分别返回且汇总为 `total`。
- Runner 是全局 ADMIN 资源。非 ADMIN 返回 `visibility=ADMIN_ONLY/status=HIDDEN` 且全部数量为 null，不读取 heartbeat；ADMIN 复用既有 heartbeat 判定。Redis 不可用时返回 `available=false/status=UNKNOWN`，online/offline 为 null，不能伪装成 0 台在线。
- 最近 Run 只来自上述可见 ACTIVE 项目，按 `created_at desc, id desc` 稳定排序，最多 10 条，并给相对报告路径。
- 每次响应返回 `generated_at`、`timezone=Asia/Shanghai`、UTC 日期范围、每项 definition 和 `read_only=true`。整个刷新路径不调用 commit/flush，不改变业务状态。

## 隔离测试覆盖

新增测试通过真实 FastAPI 路由、依赖覆盖和内存 SQLite 建立合成数据，覆盖：

- 多项目成员隔离、ADMIN 汇总、不可见/不存在统一 404、归档报告可读而 Dashboard 不计；
- API/Web/Scenario 三类历史、旧锁定版本与当前版本不同、三类持久化结果和缺失结果；
- Web 平台失败但 Step/结果成功的矛盾事实、取消、跳过、超时、未完成和空分母；
- 上海日界前后 1 秒的包含/排除、Run 重复关联 Step/Evidence 不放大 Dashboard 计数；
- Case/Step/Evidence 分页、继续路径、筛选、page_size 上限和未知参数拒绝；
- 四类真正待审 DRAFT 与不可处理占位/归档父资产排除；
- 非 ADMIN Runner 隐藏、ADMIN online/offline、Redis 不可用 unknown；
- 文本、JSON、Evidence 内部 bucket/key、AI 摘要中的合成 canary 均未进入响应；
- 请求前后数据库中的原始敏感快照逐值相同，证明脱敏和聚合只读。
