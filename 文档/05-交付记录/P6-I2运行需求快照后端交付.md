# P6-I2/r2 运行需求来源快照后端交付

## 结论

P6-I2/r2 已完成。Run 创建现在会按 CaseRun 的实际锁定目标，在同一数据库事务中保存不可变需求来源快照；报告详情、分页接口、Markdown 与 HTML 导出只读取该持久事实，不会在 Dispatch、Claim 或报告读取时根据当前关联重算。r2 进一步消除了 RequirementCaseLink identity map 旧缓存影响，所有落库 Link 字段也都来自同一条联表 SQL 的标量结果。

本包只执行隔离 SQLite、受控替身与 MySQL 方言离线 SQL 核验。没有连接或迁移正式 MySQL，没有访问正式 Redis/RabbitMQ/MinIO，没有创建正式 Run/资产，没有调用 AI，也没有启动或重启服务。

## 实现边界

新增独立模块 `app/modules/run_requirement_snapshots`：

- `run_requirement_captures` 为每个 CaseRun 保存唯一捕获头，记录状态、可靠 UTC 捕获时刻、运行目标类型、资产 ID、锁定版本 ID、条目数和一致性口径。
- `run_requirement_sources` 保存去规范化且公开安全的不可变条目：原始 Link/前序修订 ID、需求标识与捕获时名称/状态、可选 RequirementVersion 及捕获时版本号/hash/source type、I1 资产类型、运行锁定版本、原关联资产版本、两类未知绑定语义、relation/source/confidence 和 Link 审计字段。
- 来源项没有指向实时 Requirement、RequirementVersion、RequirementCaseLink 或测试资产的外键；这些实时记录后续移除、重连、归档、改名或物理级联时不会清除或改写快照。唯一生命周期级联是 CaseRun -> 捕获头 -> 来源项。
- 未保存 Requirement Markdown、请求体、Secret、AI 正文或浏览器会话。捕获 SQL 也不选择 `markdown_content`，并且不选择任何 ORM 实体。

## 捕获语义

- `API_CASE` 只匹配 I1 `TEST_CASE` ACTIVE Link；`WEB_CASE` 只匹配独立 `WEB_CASE` ACTIVE Link。
- 精确 Link 只有资产版本等于本 Run/CaseRun 锁定版本时才进入快照；同一资产的其他精确版本排除。
- 资产版本为空的旧 Link 可以捕获，但显式保存 `ASSET_VERSION_UNKNOWN`，报告明确说明不能声称精确覆盖本次运行版本。
- RequirementVersion 为空时保存 `REQUIREMENT_VERSION_UNKNOWN`，不以创建时 current 推断版本、版本号或 hash。
- 同数字 ID 的其他资产类型不会混入。需求跨项目、需求版本归属错误、Run/CaseRun 目标不一致均安全拒绝整个 Run 创建。
- 单个 CaseRun 使用 `LIMIT 1001` 检测 1000 上限；观察到第 1001 条即返回冲突并回滚，不截断后伪装成完整 `CAPTURED`。

状态口径：

- 新受支持目标有来源：`CAPTURED`。
- 新受支持目标无来源：`CAPTURED_EMPTY`。
- 新 Scenario：`UNSUPPORTED_TARGET`，明确不表示已证明不存在需求来源，不按 URL、名称或数字 ID 推断。
- 旧 Run 没有捕获头：读取时虚拟呈现 `NOT_RECORDED`，捕获时间为空，不从当前 Link 回填。

## 事务与一致数据库视图

`create_run` 先在原事务中 flush TestRun/CaseRun/StepRun 取得 CaseRun ID，再执行一次有界联表 SELECT，同时以标量列取得候选 ACTIVE Link 的全部落库字段、Requirement 展示字段与可选 RequirementVersion 展示字段，随后插入捕获头和条目并统一 commit。任何捕获异常、超限、引用不一致或提交错误都会 rollback；日志事件与 Run 状态事件仍只在 commit 成功后发生。

r2 专项复现保留了原 Session 内 Requirement 与 RequirementCaseLink 的旧强引用，同时由另一个 Session 提交标题、需求版本、资产版本、关系、来源、置信度和审计字段。捕获结果全部采用新提交的同一 SQL 视图，不受旧 identity map 实体影响；没有使用逐行 refresh、全局 expire、额外 commit 或第二个读取视图。

- MySQL 默认 Repeatable Read 下，该联表语句属于当前事务的一致快照。
- Read Committed 下，该联表语句本身是单语句一致视图。
- 没有“先枚举 Link，再逐条读取 current/版本”的 N+1 水合过程，因此不会拼接出数据库中从未同时存在的状态。

真实 MySQL 上 Link 新增/移除/重连并发竞态按契约留给后续独立 MySQL 验收包；本包不声称已完成该正式并发验证。

## 报告与导出

- 新增 `GET /api/v1/reports/{run_id}/requirement-sources`，沿用报告项目权限，支持 page/page_size 与可选 case_run_id；不属于该 Run 的 CaseRun 不返回任何捕获或来源数据。
- Case 报告带 `requirement_capture`；详情响应带首屏有界 `requirement_sources`，通过 total/has_more/next_page/continuation_path 明确续页，不把首屏当完整结果。
- Markdown/HTML 导出在现有独占一致读事务中收集完整来源，稳定校验 ID/总数，并新增 2000 条同步导出计数上限；内容继续受 16 MiB UTF-8 总输出限制。
- 导出同时显示捕获状态、捕获时间口径、资产/需求版本绑定语义与来源明细；旧 Run 显示 `NOT_RECORDED` 和空捕获时间。
