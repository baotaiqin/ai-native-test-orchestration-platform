# P6-X1 报告导出后端交付

```text
GET /api/v1/reports/{run_id}/export?format=markdown

```

导出严格复用 P6-R1 已授权、已脱敏的报告公开模型和查询服务，不读取 MinIO 正文，不触发 AI，不启动 Run，也不产生任何业务写入。既有 P6-R1 列表、详情、Cases、Steps、Evidence 接口的行为与公开模型保持冻结。

本任务没有加载或重启本地服务，没有连接正式数据库、MinIO 或其他正式依赖。

## 3. 接口契约

`format` 是必填的闭合枚举，只接受 `markdown` 或 `html`；缺失或非法值由统一请求校验返回 422，并已在 OpenAPI 中验证为 required enum。

成功响应：

| format | Content-Type | Content-Disposition 文件名 |
| --- | --- | --- |
| `markdown` | `text/markdown; charset=utf-8` | `ai-test-report-{安全 Run slug}-{12 位 SHA256}.md` |
| `html` | `text/html; charset=utf-8` | `ai-test-report-{安全 Run slug}-{12 位 SHA256}.html` |

两种格式均返回 `attachment`、`Cache-Control: private, no-store`、`Pragma: no-cache`、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY` 和 `Referrer-Policy: no-referrer`。HTML 额外同时在响应头和文档 `<meta>` 中携带 CSP。

文件名只保留 ASCII 字母、数字、点、下划线和连字符；控制字符、引号、路径分隔符及其他不安全字符不会进入附件名，原始 Run ID 的短 SHA256 保证稳定区分。

## 4. 数据完整性与一致性

导出包含以下公开报告数据：

- Run 摘要、项目/环境/Runner/目标引用、版本与元数据基准；
- 汇总计数、状态分布、成功率及其既有空分母语义；
- 全部 Case、Step、Data Field；
- 全部 Evidence 元数据和受保护下载路径，不包含对象存储正文或内部对象键；
- 既有公开模型提供的 AI Failure Analysis / Healing Proposal 最新预览、总数和继续查看路径；不扩大为原始 AI 内容或未公开审计历史。

实现先通过详情接口完成项目授权和总数预检，再以固定 `page_size=100` 调用现有公开分页服务收集全部数据。每页都核对总数、页码、记录 ID 唯一性和最终收集数量；导出期间如发生页漂移，返回稳定错误，不产生 200 部分附件。

P6-X1/r2 修复了“SQLAlchemy 逻辑事务已开始，但 SQLite 驱动尚未建立数据库读快照”导致的混合版本问题。每次导出现在从调用者 Session 的 bind 派生一个**独立且由导出模块拥有**的连接和 Session：

- SQLite：在任何报告查询前显式执行 `BEGIN`，使首个详情查询建立 WAL 读快照；后续 Case/Step/Evidence 分页持续读取同一个数据库快照。
- MySQL/InnoDB：仅在独立连接上设置 `REPEATABLE READ`，随后执行 `START TRANSACTION WITH CONSISTENT SNAPSHOT, READ ONLY`。这是因为 MySQL 官方文档明确说明一致快照修饰符只有在允许一致读的隔离级别下才有效；参见 [MySQL START TRANSACTION 文档](https://dev.mysql.com/doc/refman/8.4/en/commit.html)。
- 清理：独立 Session 关闭后，在嵌套 `finally` 中只回滚和关闭独立连接；调用者 Session 的既有事务不提交、不回滚、不替换。
- 单连接内存 SQLite：若调用者已有事务，无法安全获得第二个物理连接，则直接返回 `REPORT_EXPORT_SNAPSHOT_CHANGED`，不会在外部事务内嵌套 `BEGIN` 或误回滚调用者事务。

真实文件 SQLite WAL 双连接回归覆盖两类竞态：详情汇总后并发把 Case 状态从 SUCCESS 改为 FAILED；第一页后并发修改第二页最后一条 Case 字段。导出均完整保留变更前的一致旧快照，没有混合汇总/明细或跨页字段。状态用例还确认调用者已有读事务在导出后仍是同一个活动事务对象。

终态 Run 形成稳定报告快照；非终态 Run 明确标记“当前 Run 尚未终态，快照可能继续变化”。

数据库访问使用导出独占的一致性只读 Session；测试监听到的业务语句全部是 `SELECT`，另有 SQLite 快照边界所需的 `BEGIN`，没有 DML。105 Case + 105 Step + 105 Evidence 的跨首页样本完整输出并保持稳定顺序；查询增长由分页数决定，满足 `expanded <= base + 40` 且小于 105，不存在逐行 N+1。

## 5. 同步导出上限与错误

| 资源 | 精确上限 |
| --- | ---: |
| Cases | 2,000 |
| Steps | 10,000 |
| Evidence | 5,000 |
| 最终 UTF-8 字节数 | 16 MiB（16,777,216） |

稳定错误：

| code | HTTP | 场景 |
| --- | ---: | --- |
| `REPORT_EXPORT_LIMIT_EXCEEDED` | 413 | 任一数量或最终 UTF-8 字节超过上限；details 含 resource、limit、observed |
| `REPORT_EXPORT_SNAPSHOT_CHANGED` | 409 | 分页期间总数、页码、唯一 ID 或最终数量不一致 |
| `REPORT_EXPORT_ENCODING_ERROR` | 409 | 动态内容不能被严格编码为 UTF-8 |

数量在完整分页前预检；内容通过增量 UTF-8 writer 在构建过程中检查。边界值可成功，`+1` 稳定失败；所有失败都发生在响应创建前，不截断、不降级、不返回 200 部分文件。

## 6. 安全设计

### 6.1 HTML

- 所有动态文本经 `html.escape(..., quote=True)` 后进入 HTML；动态值只出现在文本节点中。
- 文档无脚本、事件处理器、iframe、form 或动态外部资源标签。
- 仅包含固定内联 CSS；CSP 为：

```text
default-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'; object-src 'none'; script-src 'none'; connect-src 'none'; img-src 'none'; media-src 'none'; font-src 'none'; style-src 'unsafe-inline'
```

### 6.2 Markdown

- 动态换行被折叠为可见符号，反斜线先转义；其余 ASCII 标点全部反斜线转义。
- 原始 HTML、Markdown 图片、链接、表格分隔符和代码围栏不能由动态内容构造。
- URL 仍以可审计文字出现，但不会成为可点击链接或可加载图片。

恶意载荷覆盖 Project、Environment、API Case、Run、Case、Step、Evidence、Failure Analysis 和 Healing Proposal；数据库快照在导出前后相同。
