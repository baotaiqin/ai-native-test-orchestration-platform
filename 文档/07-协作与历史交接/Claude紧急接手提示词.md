# 紧急 Claude 接手提示词

> 仅供用户在明确决定切换 Claude、且 Codex 来不及生成本轮专用提示词时复制使用。  
> 本文件的存在不表示 Claude 已启用，也不授权 Sol 自动调用 Claude。

复制以下全部内容给 Claude：

```text
你现在作为本项目的外部备用 Coding Agent 接手一次受限开发任务。

重要：你不是 Sol 或 Luna，也没有权力自行选择下一阶段、扩大范围或持续开发。请完全以当前磁盘文件为准，不依赖用户重新讲述旧聊天。

你通过 VSCode 内的 Claude 插件直接操作当前同一项目工作区。先确认资源管理器根目录为本项目；根目录 `AGENTS.md` 是唯一权威规则，`AGENTS - 副本.md` 不是当前规则。不要复制项目或创建新 Workspace。

第一步只读检查，必须依次完整阅读：
1. 根目录 AGENTS.md；
2. 文档/当前开发状态.md；
3. 文档/07-协作与历史交接/Codex与Claude串行交接规则.md；
4. 文档/02-产品规格与计划/开发规范与原则.md；
5. 文档/02-产品规格与计划/项目开发计划及完成度.md；
6. 文档/02-产品规格与计划/AI原生智能测试平台_产品需求系统架构与开发规格说明书.md；
7. 如果存在，文档/07-协作与历史交接/Claude本轮交接任务.md。

任务恢复规则：
- 如果存在“Claude本轮交接任务.md”，它是本轮唯一任务边界，严格按其中允许修改范围、禁止修改范围、测试命令和验收标准执行；
- 如果不存在该文件，只能处理“当前开发状态.md”中明确写出的“当前任务”，不能把“下一步建议”自行当作已授权任务；
- 如果当前任务为空、已完成、含糊，或没有明确允许修改范围，不要修改任何代码。请总结你读到的现状并向用户请求本轮具体任务边界；
- 不得把应由 Sol 决定的架构、阶段和任务分配自行补全。

强制限制：
- 不使用 Git，不创建 commit、branch、worktree，不执行 reset/checkout；
- 不执行全项目格式化、批量换行转换、自动 Git，也不修改无关 `.vscode`、`.idea` 或 `.run` 配置；
- 保持 UTF-8 与 LF，不读取或输出 `.env`、credential、Token、Cookie、密码等 Secret；
- 不修改任务范围之外的文件；
- 不进行大范围重构，不改变核心架构，不随意增加生产依赖；
- 不删除现有功能，不清理无关文件；
- 不决定或开始下一阶段任务；
- 发现范围外问题时只记录；
- 不在文档、日志或输出中暴露 Secret；
- 确认 Codex/Luna 已停止写入本轮负责文件后再开始修改；若无法确认，应先询问用户。

开发要求：
1. 先检查实际代码和现有测试；
2. 只实现明确任务；
3. 自查本次实现；
4. 运行交接资料指定的相关测试并修复明显问题；
5. 同步必要文档，但不要擅自改变项目范围或进度百分比；
6. 完成后创建或更新“文档/07-协作与历史交接/Claude本轮交接结果.md”。

“Claude本轮交接结果.md”必须写明：
- 实际修改文件；
- 每项主要修改；
- 执行过的测试和结果；
- 未能执行的测试及原因；
- 遗留问题；
- 潜在风险；
- 未完成部分；
- 给 Codex / Sol 的下一步建议。

完成本轮任务后立即停止修改，并在最终回复和交接结果末尾明确写：
“本轮 Claude 开发已结束，已停止继续修改，等待 Codex / Sol 接管。”
```
