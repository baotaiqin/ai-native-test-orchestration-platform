# 主控调度与执行任务协作协议

2026-09-10。用户要求执行任务不能相互通信，所有协调经过主控，并解决工作未结束就收到新任务的问题。本文是根目录 AGENTS.md 的实施规范。

## 问题依据与边界

已读取实际任务记录：DevOps 的轮次 `01a08692-a396-74e1-9e46-b79153c7d25e` 向 Backend、Runner、Frontend 共发送 7 条消息，其中包含通知 Frontend 可以读取最新结果。Frontend 在原交付后又进入新轮次。Backend 在等主控决定时调用过 wait_threads 等待主控结束；主控同时等待 Backend，造成不必要的双向等待。

主控也在 Backend 的长任务内连续追加排查、修复和恢复要求。一个任务包跨过代码修改、服务重启、队列恢复、真实 AI 验收等多个依赖边界，难以判断当前负责范围及完成点。仅在内存保存“已完成任务列表”不能覆盖后续消息重新唤醒的状态。

这些事实证明存在越过主控的调度、额外唤醒和任务范围漂移，但不能据此断言每条新消息都会终止命令，或将最新 interrupted 的原因全部归因于消息。轮次状态和后台进程状态必须分开核查。

当前工具可以向指定任务发送后续提示，未提供已经验证的“按执行任务撤销消息权限”配置。本协议落实项目行为约束；应用层强制隔离需要宿主提供按调用者和目标校验的工具权限，不能靠修改 Markdown 声称实现。

## 唯一通信路径

主控派发任务包 → 执行任务完成限定工作 → 独占交付文件及本任务 final → 主控拉取、审查 → 下一任务包。

- 执行任务不调用任何跨任务发送、创建、派发或等待工具，包括向主控发送进度消息。所有跨模块问题写入自己的报告，主控负责读取和转化为任务。
- 主控使用带游标的 wait_threads 批量观察；必要时 read_thread，不以发消息查询进度。不发送“收到”“继续等”“对方好了”等仅为通知的消息。
- 收到旧的执行任务消息时，不回复、不派生工作；保留当前主控任务包范围，在报告记录来源和冲突，由主控裁决。
- 共享报告是交付物，不是旁路命令信箱。执行任务不得往其他任务报告里写指令，也不得自行轮询其他报告开启下游工作。

## 任务包与状态

主控台账每包记录：编号/修订、目标执行任务、目标与完成边界、允许写入文件、共享服务/资产操作权、前置依赖及对应版本或 manifest、禁止事项、验证标准、报告路径、发送结果、实际 turnId 与状态。

状态为：待派发 → 执行中 → 已交付 → 已验收；执行中也可进入阻塞或中断待核查。阻塞与中断不能自动转为已验收。

1. 发送前读取目标最新轮次，确认无活动工作；确认依赖已验收、没有写入冲突，然后更新台账并发送一次完整任务包。
2. 若发送响应不确定，先读取目标历史确认是否已收到，不盲目重发。相同编号/修订重复出现时执行任务只续接已有包，不重跑外部副作用。
3. 执行中保持范围不变。普通审查意见放入主控待办，待交付后合并成一次返工包，不拆成多条即时消息。
4. 执行任务在阶段完成、关键阻塞或结束时更新独占报告，无需为每条命令记录流水账。结束前列出改动、测试、未完成项、遗留进程和恢复点。
5. 阻塞时完成可独立完成的包内工作，报告缺少的条件并结束本轮；由主控派上游任务，条件满足后再恢复。
6. 只有工具显示轮次结束且报告/源码/测试足以支持结论，主控才标记已验收。notLoaded 只是加载状态。
7. 主控持续观察已派发工作；用户要求分析/暂停调度时可先处理该要求，明确保留未完成包，不能把中断伪装为验收完成。

## 并行与串行边界

无依赖且文件/服务操作权独立的任务可以并行。代码修复 → 主控审查 → 服务加载 → 真实业务验收 → 前端真实只读验收必须按依赖串行，不为了让四个任务都忙而提前启动下游。

本次 P5-E 恢复采用以下后续包，当前仅规划、不自动派发：

1. Backend 收口已落盘 Healing 修复、显式恢复入口及测试，交付即结束；此包不重启服务、不调用真实 AI。
2. 主控审查完成后，DevOps 只加载已验收代码并交付新的就绪记录；不得自行通知 Backend/Frontend 开工。
3. 主控核对环境后，Backend 在原资产和持久调用账本上执行已授权真实闭环；每个外部结果未知时停止并交付检查点。
4. Backend 闭环交付并审查后，Frontend 读取固定 manifest 做最终只读验收。

每包只写自己的报告；主控独占台账、跨模块结论和全局状态文档。现有专属业务文件职责不变，Sol/xhigh 配置不变，旧 Luna 不调度。

## 紧急停止与恢复

用户要求立即停止或有迫近的破坏/泄露/越权/并行写入风险时，主控可发一次明确停止通知。通知必须列明停止哪些写入或外部操作、保留哪些结果以及需要返回的检查点。普通范围调整等待包结束。

中断后核对最近命令是否仍在执行、所属子进程、已修改文件、服务代码版本、消息/Run/AI账本和已提交副作用。确认前不释放共享资源操作权，不启动同文件写入者，不重复 AI POST、队列重投、批准或运行。
